# GLES Mod 玩家手册

> 这份文档写给**不写代码**的玩家。
> 不会出现术语，用不上的技术细节一律不写。
> 如果你想看技术细节，请转 [`docs/DEVELOPER-GUIDE.md`](docs/DEVELOPER-GUIDE.md)。

---

## 一、这个模组是干什么的

**让安卓手机上的《我的世界》Java 版跑得更顺。**

手机上玩 Java 版，需要有人把电脑版《我的世界》发出的画面指令，
翻译成手机显卡听得懂的指令。以前这件事由一个"翻译官"来做 ——
你每挥一次手、每转一次视角，中间都要翻译成千上万次。

这个模组换了个做法：**不做翻译，直接说手机显卡的母语。**

结果就是中间那道翻译工序没了。画面该有的还是那样，但中间少了一层开销。

---

## 二、我装了它，能得到什么

| 你关心的 | 实际效果 |
|---|---|
| 帧数 | 通常更高，因为它少了一层翻译。**具体多少取决于你的手机**，我们不虚报数字 |
| 画面 | 和原来一样。它不做画质增强，也不做美颜 |
| 光影包 | 部分能用。需要手机支持的功能没有的，会被**明确跳过并记录原因**，不是悄悄坏掉 |
| 稳定性 | 设计目标是**任何情况下都不闪退**。有功能用不了就降级，而不是崩溃 |

**它不做什么**（免得你期待落空）：

- 不会让不支持光影的手机支持光影
- 不会提升画质上限
- 不会让你用上手机显卡没有的能力

## 三、装什么、怎么装

**要装两样东西，它们分工不同。**

### 第 1 样：模组文件（`glesmod-1.0.0.jar`）

放进 `mods` 文件夹。

**作用**：报告状态、识别优化模组、写日志。
**它本身不会改变渲染。** 只装它，你什么都感觉不到。

### 第 2 样：渲染器插件（`glesmod-renderer-plugin.apk`）

像装普通安卓应用一样装上去。

**作用**：真正的渲染能力在这里面。这是让它生效的关键。

装完之后：

1. 打开启动器（FCL）
2. 找到 **渲染器 / Render** 设置
3. 在列表里选中 **「GLES Mod (native OpenGL ES)」**
4. 启动游戏

> **最常见的误会：只装了 jar，没装插件。** 那样不会有任何变化。
> 因为真正的渲染能力**不在 jar 里**，在插件里。

## 四、怎么确认它真的生效了

游戏启动后，到 `versions/<你的版本>/glesmod/` 目录下找 **`status.json`**。

用文本编辑器打开，找到这一行：

```json
"active": true,
```

- `true` = 生效了 ✅
- `false` 或文件不存在 = 没生效 ❌

同时你应该在游戏日志里看到类似这一段：

```
GLES 后端已激活，GLES 3.2，无功能降级。
```

看到「已激活」，就成了。

## 五、那些看起来吓人但**很正常**的提示

启动日志里会有一堆红字黄字。**大部分和本模组无关，也不是问题。**
下面这些你**可以放心忽略**：

| 日志里的话 | 为什么不是问题 |
|---|---|
| `Could not find any graphics adapters!` | 安卓上就是探测不到，属于正常 |
| `Sodium has applied workarounds [NO_ERROR_CONTEXT_UNSUPPORTED]` | 优化模组在做自我保护，正常 |
| `Requested GL version 4.6 got version 4.0` | 我们需要手机报 3.2，这是预期结果 |
| `Skipping shader 'xxx' (missing required features: …)` | **这是好事** —— 手机没这个能力，它主动跳过了，而不是硬上导致崩溃 |
| `Flywheel backend fell back from 'indirect' to 'instancing'` | 这是**我们主动做的降级**，性能略降但更稳 |
| `Multi-Bind unsupported, using legacy` | 同上，走了兼容路线 |
| `Error loading class: …`（一堆英文类名） | 其它模组的兼容代码没找到目标，**与本模组无关** |
| `PKIX path building failed` | 手机证书问题，只影响"检查更新"，与游戏无关 |
| `AccessDeniedException: /sys/devices/system/cpu/...` | 安卓不让读系统文件，无害 |

### 唯一需要你留意的两类

| 日志里的话 | 含义 | 你该做什么 |
|---|---|---|
| `着色器编译失败` / `Failed to create shader` | 某个着色器没编译成功 | 不影响游戏运行，但那个效果会缺失。**把 `glesmod/native.log` 发给开发者**，里面有完整原因 |
| `降级事件` 里出现你没见过的项目 | 某个功能被降级了 | 看它写的"替代方案"，如果还能接受就继续玩 |

## 六、遇到问题怎么办

### 情况 1：装了没反应，`active` 是 `false`

按顺序检查：

1. **插件装了吗？** 不是只有 jar —— APK 也必须装。
2. **在启动器里选中了吗？** FCL 的 Render 设置里要手动选「GLES Mod」。
3. **版本对吗？** 需要 Minecraft **1.21.1** + NeoForge **21.1.241**。
4. 还不行的话，把 `status.json` 和 `latest.log` 发给开发者。

### 情况 2：游戏直接闪退

1. 先在启动器里**换回原来的渲染器**（选内置的、或别的），游戏就能正常开了。
2. 把崩溃日志（`crash-reports` 目录里的文件）发给开发者。

### 情况 3：画面花屏 / 贴图错位 / 有东西不见了

这属于**画面问题**，请提供：

- `glesmod/status.json`
- `glesmod/native.log`（如果存在）
- `latest.log`
- 一张问题截图

**log 比描述更有用。** 光说"花了"很难定位，日志里通常有准确原因。

### 情况 4：某效果不见了（比如光影包的一部分）

先看日志里有没有 `Skipping shader`。
如果有，说明那个效果需要手机没有的能力 —— **这是设计上的取舍，不是 bug**，
跳过它比强行运行导致崩溃好。

## 七、和其它模组一起用

### 没问题，放心装

- **Sodium / Embeddium**（性能优化模组）：**已实测可用**，帧数与它们单独使用时相当
- **Sodium Extra**、**Iris**（光影加载器）
- **机械动力（Create）** 及其附属
- **Flywheel**、**Veil**、**Sable** 等渲染相关模组

### 需要注意

- 如果你装了**未经测试的 Sodium 版本**，模组会走**保守路线**并在日志里告诉你。
  这是刻意的：宁可稳一点，不去猜它内部怎么实现的。
- 某些老旧的优化模组可能不兼容。日志里会体现。

> **重要原则**：本模组**不修改**其它模组的代码。
> 它只读取版本信息来决定自己的策略。所以它不会和别的模组"打架"。

## 八、配置项（想调的人看）

启动器的插件设置里能看到几个开关。**默认值就是推荐值**，不懂就别动。

| 选项 | 默认 | 作用 |
|---|---|---|
| 降级档位 | 1 | `0` 最保守（最稳），`1` 默认，`2` 最激进（最快）。**追求稳就调 0，追求帧数可以试 2** |
| 总开关 | 开 | 关掉后本模组什么都不做 |
| 详细日志 | 开 | 排查问题时建议保持开启 |

**改配置后需要重启游戏**，因为有些设置是在游戏启动前读取的。

## 九、它到底是怎么做到的（一句话版）

> 电脑版《我的世界》说的是"电脑显卡方言"，
> 手机显卡听的是"手机方言"。以前中间站着一个翻译，
> 每句话都要翻译一遍。这个模组**直接教游戏说手机方言**，
> 所以翻译不用了。

如果你想知道更具体的东西 —— 比如"它怎么处理方言不一样的词" ——
那要看 [`docs/DEVELOPER-GUIDE.md`](docs/DEVELOPER-GUIDE.md)。

## 十、常见疑问

**问：会不会封号？**
答：不会。它不是外挂，不改游戏内容，只是换了渲染方式。服务器看不到区别。

**问：会不会改我的存档？**
答：不会。它只管画面，完全不碰存档数据。

**问：会不会更耗电 / 更烫？**
答：通常**更省**，因为它少做了一层翻译。但帧数变高的话，功耗也可能跟着上去 ——
这是帧数带来的，不是它本身的问题。想省电可以限制帧数。

**问：为什么不直接显示成"光影全支持"？**
答：因为那是假的。手机显卡确实没有某些能力（比如计算着色器）。
我们选择**如实告诉你哪些被跳过了**，而不是假装支持然后出错。

**问：它和 GL4ES、ANGLE 是什么关系？**
答：它们是**替代关系**。那些是"翻译官"，本模组是"直接说母语"。
同一个位置只能站一个，所以在启动器里选中本模组后，就不再走那些翻译官了。

**问：日志里红字好多，是不是坏了？**
答：先看第五节。绝大多数红字来自其它模组或安卓系统，**与本模组无关**。
判断是否生效，只看 `status.json` 里的 `"active": true`。

## 十一、反馈问题时请附上

1. **`glesmod/status.json`** —— 最重要，它记录了后端状态和能力
2. **`glesmod/native.log`** —— 如果存在，里面有详细过程
3. **`latest.log`** —— 游戏日志
4. 手机型号、安卓版本
5. 问题现象截图或清晰描述

位置都在 `versions/<你的版本>/` 下面。

> 少给一项，排查就可能要多一轮来回。日志齐全的话，大多数问题能**一次定位**。
